# PICASO 원본 결측 파일 요청 목록

- 작성일: 2026-08-31
- 대상: `0_database/picaso/` (쿡·팔라우 동일 결측)
- 목적: `acidwg-picaso-convert` 가 `[MISS]` 로 건너뛰는 조합 해소

## 1. 요청할 파일 (8개 = 4조합 × prec/t2m)

| 대상 월 | 리드타임 | 강수(prec) | 기온(t2m) | 이 파일이 막고 있는 조합 |
|---|---|---|---|---|
| 2026-01 | LT1 | `TP_JAN_2026_LT1.csv` | `TT_JAN_2026_LT1.csv` | **2026_JFM** |
| 2025-01 | LT2 | `TP_JAN_2025_LT2.csv` | `TT_JAN_2025_LT2.csv` | 2024_DJF |
| 2025-01 | LT3 | `TP_JAN_2025_LT3.csv` | `TT_JAN_2025_LT3.csv` | 2024_NDJ |
| 2025-02 | LT3 | `TP_FEB_2025_LT3.csv` | `TT_FEB_2025_LT3.csv` | 2024_DJF |

2026_JFM 만 필요하면 **첫 줄 2개**(JAN 2026 LT1)만 받으면 된다.

## 2. 저장 위치 (받은 뒤 그대로 넣으면 됨)

```
0_database/picaso/prec/{월코드}/{연도}/TP_{월코드}_{연도}_LT{n}.csv
0_database/picaso/t2m /{월코드}/{연도}/TT_{월코드}_{연도}_LT{n}.csv
```

예) `0_database/picaso/prec/JAN/2026/TP_JAN_2026_LT1.csv`

쿡(`I:\2025-APCC_Cook\PICASO-Hydro`)·팔라우(`I:\2025-APCC_Palau\PICASO-Hydro`) 양쪽 모두 동일 위치에 넣는다.
수집 원본은 `2025-APCC_Palau\Database\_collected\` 아래에 배포본 폴더째로 보관한다.

## 3. 파일 형식 (기존 배포본과 동일해야 함)

헤더 15열:
`stnid,an,nn,bn,Fcst,Category,fcst_min,fcst_max,fcst_md,fcst_mean,fcst_std,fcst_lb,fcst_ub,fcst_lx,fcst_ux`

- 월별 LT 파일은 관측소 10개 (팔라우 91408, 쿡 91843 포함)
- `an+nn+bn = 100`

## 4. 반영 후 실행 절차

```bash
cd I:\2025-APCC_Cook\PICASO-Hydro        # 팔라우도 동일
acidwg-picaso-convert --seasons JFM --years 2026   # 1_acidwg/picaso 생성
acidwg-run --forecast 2026_JFM                     # 1_acidwg/forecast 생성
```

이미 있는 산출물은 건너뛰므로 위 명령을 그대로 반복해도 안전하다.

## 5. 근거 (확인 내용)

- 배포 이력
  - 2026-03-27 배치: JAN 2026 LT2·LT3, FEB 2026 LT3
  - 2026-08-30 배치: `PICASO26FMA_prec_t2m.zip` — FEB/MAR/APR 2026 각 LT1~3 + FMA 계절 (총 20개)
- 배포 단위는 **계절 패키지**로 보인다(FMA 패키지 = FMA 3개월 × LT1~3).
  따라서 JFM 패키지를 통째로 요청하면 JAN 2026 LT1 이 포함될 가능성이 높다.
- `PICASO26FMA_prec_t2m.zip` 내부를 확인한 결과 JAN 파일은 들어 있지 않다(csv 20개, JAN 0개).
- 수집 폴더 전체에서 `*JAN_2026_LT1*` 검색 결과 없음.
- 2026_MAM·2026_AMJ 도 `[MISS]` 지만 이는 5·6월 예측이라 **아직 발표 전**인 정상 상태다.
